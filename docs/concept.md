# Kizamu 初期コンセプト

Kizamuは、作業を中断せず、プロジェクトごとの時間を素早く記録するタイムトラッカーです。

## 記録操作

中心となるのは時間記録の気軽な開始と終了です。開始時にプロジェクト、作業分類、集計用属性などを強制せず、未分類でも記録し、必要になった時点で後から整理できることを重視します。

複数の作業を同時に記録できることを基本要件とします。別の作業やプロジェクトを表示・操作することは、既に進行中の記録を自動的に終了する理由にはなりません。各記録は独立して開始・終了し、終了は対象の記録に対する明示的な操作とします。

MVPでは作業ノードを扱わないため、作業の種別はプロジェクトの違いだけで区別します。プロジェクト未指定も一つの既定の作業種別として扱います。同じ作業種別の記録は同時に一件だけ進行でき、異なるプロジェクトの記録は同時に進行できます。将来、プロジェクト内の作業を扱う段階では、作業種別の識別をプロジェクトから作業へ拡張します。

## 記録と管理の分離

記録、管理、集計は同じデータを扱っても目的の異なる操作です。記録画面は開始・終了・切替を素早く行い、管理画面はプロジェクトや作業構造を整理し、集計画面は記録結果を確認します。記録用UIを集計表や管理画面の一部として設計しません。

## プロジェクトと作業ツリー

プロジェクトは時間を整理・集計する主要概念ですが、毎回の記録操作の前提にはしません。プロジェクト配下には、階層ごとの固定名や意味を持たない汎用的な作業ノードのツリーを置く構想です。

```text
プロジェクト
└─ 作業ノード
   └─ 作業ノード
      └─ 作業ノード
```

通常のUIでは二階層程度を扱いやすくしますが、データ構造の深さは制限しません。深い階層を推奨せず、必要な利用者には分類の自由を残します。時間記録は末端に限らず任意の作業ノードへ紐付けられる構想です。作業ツリーはMVPには含めず、ログインや利用者ごとのデータ管理より後の候補とします。

登録したプロジェクトはタブとして素早く切り替えられる構想とします。タブ切替は表示・操作対象の切替であり、他のプロジェクトで進行中の記録を終了しません。複数プロジェクトの記録状態を保ったまま行き来できることを、Kizamuの特徴として扱います。

## 管理方針

管理できる仕組みは用意しつつ、管理そのものへ多くの手間を要求しません。便利な既定を提示しても、UIで利用者の考え方や分類方法を過度に規定しません。

## 将来候補

プロジェクト管理、任意深度の作業ツリー、時間記録の開始・終了・切替、未分類記録の後整理、集計、時間配分、Clockifyとの双方向同期、独立したデータ管理、ローカル保存、サーバー永続化、ログイン、ユーザー管理は将来候補であり、未実装です。

時間配分は補助機能であり主機能ではありません。Clockify連携も補助画面ではなく、独立したKizamuが外部サービスとの相互運用性を持つ位置付けです。
