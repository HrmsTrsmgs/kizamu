# 工程担当の共通規則

共通 `tdd-workflow/references/common.md`（`codex-workflows e66db1d`）のリポジトリ内参照版。

この文書と自分の工程文書だけを工程指示として読む。適用されるAGENTS、安全・Git規則、対象技術の規約は守るが、進行役手順、他工程の指示、過去の議論、未採用案、候補一覧、モデル選択の議論は読まない。必要なコード・テストは担当範囲で自分で取得する。

同じ作業ツリーを順番に編集し、既存差分を保全する。別工程を兼任せず、担当同士の相談や再委任をしない。要求・確定契約・提案・未確認を区別し、未決定の外部契約が不可欠なら停止して必要な判断だけを返す。

成功、失敗、Skip、未実行を区別して対象・必要な回帰を検証する。コード変更のGreen・Refactor完了時とコミット前は原則として影響する実装の全テストを確認し、残りに影響しないことを依存関係・実行経路から説明できる場合だけ範囲を絞って理由を報告する。所要時間だけを省略理由にしない。検証対象版・設定・実行条件が同じ結果を、工程の受け渡しだけのために再取得しない。

未コミット差分を残し、成果物の場所、テスト結果、停止理由、発見した検討事項だけを簡潔に進行役へ返す。長い思考履歴は渡さない。人間のIDE等での確認と了承前にステージ・コミットしない。コミット・push・merge・releaseは進行役がユーザーの指示に従って扱う。
